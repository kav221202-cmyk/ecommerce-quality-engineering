# Defect Reports

## 1. Defect Management Overview

This document contains defect reports identified during the testing of the SauceDemo e-commerce application.

Defects are documented using a standardized format to ensure that issues can be clearly understood, reproduced, prioritized, investigated, and tracked through their lifecycle.

No defect is reported unless it can be reproduced and confirmed as an actual deviation from the expected behavior.

---

## 2. Defect Severity

Severity represents the technical impact of a defect on the application.

| Severity | Description |
|----------|-------------|
| Critical | The application or a critical business function is completely unavailable or unusable. |
| High | A major function is broken and there is no reasonable workaround. |
| Medium | A functional issue affects normal usage but the application remains usable. |
| Low | A minor issue with limited functional impact, such as a small UI or cosmetic problem. |

---

## 3. Defect Priority

Priority represents how urgently a defect should be fixed.

| Priority | Description |
|----------|-------------|
| P1 - Critical | Requires immediate attention. |
| P2 - High | Should be fixed as soon as possible. |
| P3 - Medium | Should be fixed in a future development cycle. |
| P4 - Low | Can be addressed when resources are available. |

---
